02 / The workflow

Main and Verifier keep working.

Main owns requirements, dispatch, and process. The persistent Verifier independently inspects every actual change, integrates, tests, and repairs.

DESIGNER

Light architecture

Define independently deliverable milestones, interfaces, and real dependencies. Hand off without exhaustive implementation design.

WORKERS

Implement in parallel

Group Workers by functional domain within actual host resources, without fixed group sizes. Output stays untrusted until independently inspected.

VERIFIER

Inspect actual work

Check each change independently. Integrate and test continuously. Repair defects directly or inspect returned implementation repairs.

A separate Reviewer closes an immutable milestone candidate from requirements and code while the persistent Verifier continues other work.

Independent Adversary, across any assigned roles

The coordinator names targets. Adversary investigates immediately and sends opinions directly, or the coordinator relays them unchanged. Main, Designer, Worker domains, Verifier, and Reviewer can all be challenged.

04 / Design and implementation

DESIGNER

Architecture and
complete outcomes.

Separate an independently deliverable existing bug fix, necessary refactor, and new feature. Use real dependencies rather than artificial ordering.

Ordinary implementation errors remain inside their feature. Discoveries update affected work; they do not automatically restart design.
WORKER

Implementation only.

Execute <node> in <plan>.
Repository: <repo>.

Choose implementation details and resolve ordinary coding problems. Hand back the actual change for independent inspection.

No QA, process, integration, or mandatory evidence-pack duty. Worker claims are not proof. Parallelism does not imply unlimited or free compute; host configuration stays intact.

05 / Adversary

Independent challenge.
Any collaboration structure.

A coordinator explicitly assigns one or more named targets. Plans and requirements inform judgment, but neither is a prerequisite or the sole authority on correctness.

Named targets

Main, Designer, Worker, Verifier, or Reviewer. Group Worker targets by functional domain and name the agents in each domain.

Immediate investigation

Examine actual activity and goals, host capabilities, project and organization rules, local guidance, and relevant external docs and best practices.

Opinions to the target

Question infeasibility, odd or wasteful behavior, coupling, privacy risks, and mistaken assumptions. Message directly or relay unchanged through the coordinator.

Advice without taking over

Adversary never edits code, documents, or plans, and never repairs or integrates. Targets keep their responsibilities. No veto, mandatory evidence pack, runtime service, schema, or scheduler.

06 / Independent closure

A separate Reviewer.
A stable candidate.

Read the requirements and immutable code snapshot. Independently validate, repair, and verify the resulting candidate.

Prior Worker and Verifier conclusions
do not establish correctness.

  • Milestone closureClose useful candidates promptly. Verifier continues other work outside the frozen candidate.
  • Repair cyclesReviewer repairs receive fresh verification and return to Verifier for inspection and integration.
  • All requirementsFinal closure includes omitted requirements and cross-milestone behavior, not merely completed plan entries.
  • Simple handoffUse host messages and stable revisions. No new enforcement or human approval framework.

07 / Final handoff

Finish continuous verification.
Then begin fresh final review.

01

All Workers and milestone-review repair writes are done; corrected revisions are incorporated.

02

Verifier runs final whole-plan regression, repairs, and repeats affected verification.

03

Verifier notifies Main that the final regression is complete.

04

Main stops Verifier and confirms its writes have ended.

05

A separate final Reviewer independently validates, repairs, and closes all requirements from requirements and code.

Scoped rework can repeat this cycle. Earlier verification never replaces the final Reviewer's own judgment.
